# ALPN (응용 계층 프로토콜 협상)

## 📝 정의

ALPN은 **TLS 인사 안에서 그다음에 쓸 규약(프로토콜)을 골라 두는 확장**이다.

같은 443번 포트 위에 HTTP/1.1 과 HTTP/2 와 HTTP/3 가 함께 산다. 어느 것으로 말할지 연결을 다 맺고 나서 다시 물으면 왕복이 한 번 더 든다. RFC 7301 은 그 목적을 "클라이언트와 서버 사이에 왕복을 더하지 않고 이 협상을 해내는 것" 이라고 적었다. 그래서 인사에 칸 하나를 더해, 자물쇠가 걸리는 그 순간 규약도 함께 정해지게 했다.

### 이름
Application-Layer :: 주고받는 내용 층
Protocol :: 말하는 규칙
Negotiation :: 서로 맞춰 정함
= 붙여 읽으면 "내용 층의 규칙을 서로 맞춰 정하는 일". 인사가 끝나기 전에 그 일이 끝난다

### 비유
식당 문을 들어서면서 "한국어 메뉴판이요" 하고 미리 말해 두는 것. 앉아서 다시 부르면 그만큼 늦어진다.

### 예
같은 주소인데 어떤 사이트는 HTTP/2 로, 어떤 사이트는 HTTP/1.1 로 붙는다. 그 갈림이 인사 한 번에서 정해진다.

### 직접
크롬 개발자 도구 네트워크 탭에서 Protocol 열을 켜 보라. `h2` 나 `h3` 라고 적힌 그 값이 이 인사에서 골라진 이름이다.

## 🖼️ 그림으로 보기

```도해
흐름: 어떤 규약으로 말할지는 언제 정해지나
클라이언트 :: `ClientHello` 에 `h2, http/1.1` 을 나열한다
서버 :: 그중 하나만 고른다. 겹치는 게 없으면 끊는다
< 서버 :: 고른 이름 하나를 인사 답장에 담아 돌려준다
첫 줄 :: 인사가 끝나는 그 순간 그 규약으로 나간다
= 연결을 다 맺고 다시 묻지 않는다. 오가는 횟수를 한 번도 안 늘린다
```

## ⚠️ 해결하는 문제

```도해
대조: 이 칸이 없으면 어떻게 되나
칸이 없으면 || 칸이 있으면
정하는 때 :: 연결을 맺은 뒤 || 인사 안에서 끝
왕복 :: 한 번 더 든다 || 안 늘어난다
HTTP/2 :: 못 켜지고 내려앉음 || 그대로 켜진다
안 맞을 때 :: 붙고 나서 헤맨다 || 바로 끊고 알린다
= 규약을 고르는 일을 인사 안으로 끌어들여 왕복 한 번을 없앤 것이다
```

한 포트 위에 여러 규약을 얹으면 "지금 상대가 무엇으로 말할 셈인가" 를 알아내야 한다. 연결을 맺은 뒤에 묻는 방식은 왕복이 한 번 더 들고, 그 한 번이 첫 화면이 뜨는 시간에 그대로 얹힌다. 게다가 TLS 위의 HTTP/2 에는 평문 업그레이드 같은 우회로가 없어서, 협상 수단이 없으면 아예 HTTP/1.1 로 내려앉는다.

ALPN 은 이미 오가는 인사에 목록 한 줄을 얹는다. 클라이언트가 선호 순으로 이름을 나열하고 서버가 하나를 고르므로, 왕복은 늘지 않고 겹치는 게 없을 때는 곧바로 끊어 알려 준다.

## ⚙️ 작동 원리

클라이언트는 `ClientHello` 에 `ProtocolNameList` 를 담는다. RFC 7301 은 그것을 "클라이언트가 알리는 규약 목록, 선호도 내림차순" 으로 정의한다. 서버는 답장에 딱 하나만 담는다 — 규격이 "`ProtocolNameList` 는 정확히 하나의 `ProtocolName` 을 담아야 한다" 고 못박아 두었다. 겹치는 것이 하나도 없으면 서버는 치명 경고 `no_application_protocol` 로 인사를 끊는다.

이름은 지어내는 값이 아니라 IANA 의 ALPN Protocol IDs 목록에 등록된 바이트 열이다. `http/1.1`, HTTP/2 를 뜻하는 `h2`, HTTP/3 를 뜻하는 `h3` 가 거기 있고, DNS over TLS 의 `dot` 과 DNS over QUIC 의 `doq` 도 같은 목록에 있다. 웹 전용 장치가 아니라는 뜻이다.

한 가지 남는 것이 있다. RFC 7301 은 "클라이언트가 이 식별자들을 평문으로 보낸다" 고 적어 두었다. IANA 등록표를 보면 이 확장은 TLS 1.3 에서 `ClientHello` 와 `EncryptedExtensions` 두 곳에 쓰인다 — 서버가 고른 답은 잠긴 쪽으로 옮겨 갔지만, 클라이언트가 늘어놓는 목록은 여전히 첫 마디에 평문으로 남는다는 뜻이다. RFC 9849 가 봉투에 넣어 가려야 할 칸으로 SNI 와 함께 이 목록을 든 까닭이 그것이다.

## 💡 실제 사례

- **HTTP/2 를 켰는데 안 붙는다** — nginx 문서는 "TLS 위에서 HTTP/2 연결을 받으려면 ALPN 확장 지원이 필요하고, 이는 OpenSSL 1.0.2 부터 가능하다" 고 적는다. 옛 라이브러리로 빌드된 nginx 는 `http2 on;` 을 써도 조용히 HTTP/1.1 로 내려앉는다.
- **무엇으로 골라졌는지 확인** — `openssl s_client -alpn h2,http/1.1 -connect example.com:443` 을 치면 출력에 `ALPN protocol: h2` 한 줄이 뜬다. 목록에서 `h2` 를 빼고 한 번 더 치면 그 줄이 `http/1.1` 로 바뀐다. 못 켜진 쪽이 그쪽인지 내 쪽인지가 이 두 번으로 갈린다.
- **웹 밖에서** — DNS over TLS 는 `dot`, DNS over QUIC 는 `doq` 라는 등록된 이름으로 같은 칸에서 골라진다. 규약 이름을 등록해 두면 어떤 응용이든 이 자리를 쓸 수 있다.

## 🚫 흔한 오해

- **HTTP/2 는 설정 한 줄만 켜면 된다** — TLS 위에서는 이 협상이 받쳐 줘야 켜진다. 라이브러리가 못 받치면 오류도 없이 HTTP/1.1 로 내려앉아, 켠 줄 알고 지나가게 된다.
- **어떤 규약을 쓰는지는 밖에서 안 보인다** — 클라이언트가 늘어놓는 목록은 평문이다. TLS 1.3 에서 잠긴 것은 서버가 고른 답 쪽이다.
- **여러 개를 한꺼번에 고를 수 있다** — 서버 답장에는 반드시 하나만 담긴다. 겹치는 것이 없으면 고르는 대신 `no_application_protocol` 로 끊는다.

## 📝 정리

**"인사하면서 그다음 말투를 미리 정하는 칸"** 이라고 읽으면 된다. 왕복을 한 번도 안 늘리려고 만든 자리라, 자물쇠가 걸리는 그 순간 규약도 함께 정해진다. HTTP/2 나 HTTP/3 가 안 켜질 때 가장 먼저 볼 곳이 여기다.

**출처**

- [RFC 7301 — TLS Application-Layer Protocol Negotiation Extension](https://www.rfc-editor.org/rfc/rfc7301.html) — 왕복을 안 늘린다는 설계 목표, `ClientHello` 의 선호도순 `ProtocolNameList` 와 서버 답의 정확히 하나 규정, `no_application_protocol` 치명 경고, 클라이언트가 이 식별자들을 평문으로 보낸다는 서술을 확인
- [IANA — TLS ExtensionType Values / ALPN Protocol IDs](https://www.iana.org/assignments/tls-extensiontype-values/tls-extensiontype-values.xhtml) — 확장 번호 16번과 TLS 1.3 에서 쓰이는 자리가 `ClientHello`·`EncryptedExtensions` 라는 표기, 등록된 식별자 `http/1.1`·`h2`·`h3`·`dot`·`doq` 를 확인
- [nginx — ngx_http_v2_module](https://nginx.org/en/docs/http/ngx_http_v2_module.html) — TLS 위 HTTP/2 가 ALPN 지원을 요구하며 OpenSSL 1.0.2 부터 가능하다는 문구와 `http2` 지시어를 확인
- [RFC 9849 — TLS Encrypted Client Hello](https://www.rfc-editor.org/rfc/rfc9849.html) — 클라이언트가 늘어놓는 ALPN 목록을 SNI 와 함께 가려야 할 민감한 자리로 든 서술을 확인
