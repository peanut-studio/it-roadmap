# URL (Uniform Resource Locator)

## 📝 정의

URL은 **인터넷에서 무엇을 어디서 어떻게 가져올지 적은 주소**다.

프로토콜, 호스트, 경로, 물음표 뒤의 값까지 한 줄에 들어 있다. 브라우저는 이 한 줄을 쪼개서 어디로 접속할지와 무엇을 요청할지를 정한다.

### 이름
Uniform :: 어디서나 같은 꼴
Resource :: 가져올 것
Locator :: 자리를 짚는 것
= 붙여 읽으면 "가져올 것이 어디 있는지 같은 꼴로 짚는 말". 형식이 하나라는 것이 이름 첫 낱말이다

### 비유
택배 송장. 어느 도시, 어느 건물, 몇 호, 누구 앞인지가 한 장에 적혀 있어서 그것만 보고 배달한다.

### 예
검색 결과 화면을 그대로 보여주려고 친구에게 복사해 보내는 그 주소 한 줄이다.

### 직접
유튜브에서 아무거나 검색한 뒤, 주소창의 물음표 뒤 글자만 다른 말로 바꿔 엔터를 쳐 보라. 화면이 그 말의 결과로 바뀐다.

## 🖼️ 그림으로 보기

```도해
층: URL 한 줄은 무엇으로 나뉘나
프로토콜 :: https. 어떤 방식으로 가져올지
호스트 :: example.com. 어느 서버인지
포트와 경로 :: 443 과 /search. 어느 창구의 무엇인지
질의와 조각 :: ?q=python 과 #result. 조건과 화면 위치
= 앞쪽은 어디로 갈지, 뒤쪽은 무엇을 달라고 할지를 정한다
```

## ⚠️ 해결하는 문제

```도해
대조: 자원을 가리키는 방식이 제각각이면 어떻게 되나
표준이 없으면 || URL 로
접근 방법 :: 서버마다 다름 || 같은 형식
공유 :: 설명을 붙여야 함 || 한 줄 보내면 끝
조건 전달 :: 방법이 따로 없음 || 물음표 뒤에
= 형식을 하나로 정해두니 주소 한 줄이 곧 지시가 된다
```

주소 형식이 서버마다 다르면 링크를 걸 수도 없고 북마크할 수도 없다. 형식이 하나로 정해져 있으니 브라우저는 처음 보는 주소도 똑같이 처리할 수 있다.

물음표 뒤에 조건을 붙일 수 있다는 점도 크다. 검색어와 정렬 방식이 주소에 들어 있으면 그 화면 상태를 그대로 남에게 보낼 수 있다.

## ⚙️ 작동 원리

`https://example.com:443/search?q=python#result` 처럼 쪼개진 한 줄을 브라우저는 이런 순서로 쓴다.

```도해
흐름: 주소창에 URL 을 치면 무슨 순서로 오가나
브라우저 :: 한 줄을 프로토콜, 호스트, 경로로 쪼갠다
DNS :: 호스트 이름을 IP 주소로 바꾼다
연결 :: 그 IP 의 포트로 접속한다. https 면 443
요청 :: 경로와 물음표 뒤의 값을 서버에 보낸다
< 브라우저 :: 받은 내용을 그리고 # 뒤 위치로 이동한다
= 한 줄 안에 어디로 갈지와 무엇을 달라고 할지가 함께 있다
```

`#` 뒤는 서버로 가지 않는다. 브라우저가 페이지를 받은 다음 그 위치로 스크롤할 때만 쓰인다. 그래서 같은 페이지 안에서 `#`만 바뀌면 새로 요청하지 않는다.

주소에는 정해진 문자만 넣을 수 있어서, 공백이나 한글은 `%20` 같은 형태로 바뀐다. 브라우저가 대개 알아서 처리하지만 직접 주소를 조립할 때는 이 변환을 빠뜨리기 쉽다.

## 💡 실제 사례

- **검색 결과 공유** — 검색어와 조건이 주소에 있어서 그 한 줄만 보내면 상대가 같은 화면을 본다.
- **API 호출** — 경로로 무엇을 다룰지 정하고 물음표 뒤로 조건을 넘긴다.
- **문서 안 위치** — `#` 뒤에 소제목 이름을 붙이면 긴 문서에서 그 지점부터 보여준다.

## 🚫 흔한 오해

- **URL과 도메인은 같은 말이다** — 도메인은 URL의 한 부분이다. 어느 서버인지만 가리키고 그 안의 무엇인지는 경로가 정한다.
- **`#` 뒤에 적은 값도 서버가 받는다** — 서버로 가지 않는다. 브라우저 안에서만 쓰이므로 서버 로그에도 남지 않는다.
- **주소는 대소문자를 안 가린다** — 도메인 부분은 안 가리지만 경로는 서버에 따라 가린다. 같은 주소인데 한 글자 대문자라서 404가 나는 일이 여기서 생긴다.

## 🚨 주의사항

- **민감한 값을 물음표 뒤에 넣지 않는다.** 주소는 브라우저 기록, 서버 로그, 전달 헤더에 그대로 남는다.
- **직접 주소를 조립할 때는 값을 변환한다.** 검색어에 `&`나 공백이 들어가면 조건이 엉뚱하게 잘린다.

## 📝 정리

**"어디로 갈지와 무엇을 달라고 할지를 한 줄에 담은 그 주소"** 라고 읽으면 된다. 형식이 정해져 있어서 링크와 공유가 되고, `#` 뒤는 서버가 아니라 브라우저만 쓰는 부분이다.

## 🧒 열 살에게

택배 송장에는 어느 도시, 어느 건물, 몇 호, 누구 앞인지가 한 장에 다 적혀 있지? 그 종이만 보면 누가 맡아도 똑같이 갖다줄 수 있어. 인터넷 주소 한 줄도 그렇게 생겨서, 친구한테 그것만 보내면 친구도 네가 보던 화면을 그대로 봐.

## ❓ 이해했는지

- 같은 페이지에서 `#` 뒤만 바뀔 때 화면이 새로 뜨지 않는 이유는 → 작동 원리
- 검색어를 주소에 직접 이어 붙였더니 조건이 잘렸다면 무엇을 빠뜨린 것인가 → 주의사항
- 주소를 똑같이 쳤는데 404가 난다면 어느 부분을 의심해야 하나 → 흔한 오해

## 🔗 관련 용어

- [[DNS]] — URL 의 호스트 이름을 IP 주소로 바꾼다
- [[Domain]] — URL 에서 어느 서버인지 가리키는 부분
- [[Port]] — URL 에 적히거나 프로토콜에 따라 기본값이 붙는 번호
- [[HTTP]] — URL 로 요청하고 응답받을 때 쓰는 프로토콜
- [[REST]] — URL 의 경로를 자원 이름으로 쓰는 설계 방식
