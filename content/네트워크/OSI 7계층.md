# OSI 7계층 (OSI 7-Layer Model)

## 📝 정의

OSI 7계층은 **네트워크 통신을 일곱 단계로 나눈 참조 모델**이다.

국제표준화기구(ISO)가 정한 것으로, 신호를 선에 흘려보내는 일부터 화면에 웹 페이지를 띄우는 일까지를 층으로 갈라 각 층이 무엇을 책임지는지 정해두었다. 층마다 하는 일이 정해져 있으니 한 층을 바꿔도 위아래는 그대로 둘 수 있다.

### 이름
Open :: 아무나 따라 만들게
Systems :: 서로 다른 기계들
Interconnection :: 맞물려 통하기
Layer :: 층
Model :: 본보기 그림
= 붙여 읽으면 "다른 기계끼리 맞물리게 공개해 둔 일곱 층 본보기". 설계도가 아니라 본보기다

### 비유
국제 우편. 편지를 쓰는 사람, 봉투에 주소를 적는 사람, 비행기에 싣는 사람이 나뉘어 있고 서로의 일을 알 필요가 없다.

### 예
인터넷이 안 될 때 랜선부터 보고 그다음 공유기를 보는 그 순서가 이 층을 아래에서부터 올라가는 것이다.

### 직접
와이파이를 끄고 셀룰러 데이터로 같은 앱을 다시 써 보라. 밑에 깔린 선이 통째로 바뀌었는데 앱은 아무것도 고치지 않고 그대로 돈다 — 아래 층을 갈아 끼워도 위층은 손댈 게 없다는 뜻이다.

## 🖼️ 그림으로 보기

```도해
흐름: 웹 요청이 내려가면서 무엇이 덧붙나
응용 :: HTTP 요청을 만든다. 7계층
표현 :: 인코딩하고 필요하면 암호화한다. 6계층
세션 :: 언제 시작하고 끝낼지 관리한다. 5계층
전송 :: 포트 번호를 붙인다. 4계층
네트워크 :: IP 주소를 붙여 갈 길을 정한다. 3계층
데이터링크 :: MAC 주소를 붙인다. 바로 옆까지. 2계층
물리 :: 전기 신호로 바꿔 선에 흘린다. 1계층
= 층마다 자기 봉투를 덧씌운다. 받는 쪽은 거꾸로 하나씩 벗긴다
```

## ⚠️ 해결하는 문제

```도해
대조: 통신을 한 덩어리로 다루면 어떻게 되나
한 덩어리로 || 계층으로 나눠
매체 교체 :: 전부 다시 짬 || 아래 둘만
문제 찾기 :: 어디부터 볼지 || 아래부터 차례로
장비 호환 :: 제조사마다 다름 || 같은 기준으로
= 무엇을 바꾸든 그 층만 바꾸면 되도록 경계를 그어둔 것이다
```

통신을 나누지 않고 하나로 보면 작은 변경도 전체를 건드리는 일이 된다. 유선을 와이파이로 바꾸는 것과 브라우저가 페이지를 그리는 것은 아무 상관이 없는데도, 경계가 없으면 둘이 같은 코드 안에 엉켜 있게 된다.

계층은 그 경계를 정해준다. 위층은 아래층이 어떻게 하는지 몰라도 되고, 아래층은 위층이 무엇을 보내는지 몰라도 된다. 제조사가 달라도 같은 층에서 같은 규칙을 지키면 장비끼리 통한다.

## ⚙️ 작동 원리

내려가면서 헤더가 붙는 것을 캡슐화라고 한다. 응용 데이터에 TCP 헤더가 붙어 세그먼트가 되고, 거기에 IP 헤더가 붙어 패킷이 되고, 다시 프레임 헤더가 붙어 프레임이 된다. 받는 쪽은 반대 순서로 헤더를 떼면서 올린다.

```도해
층: 실무에서는 이 일곱을 어떻게 묶어 보나
응용 (7·6·5) :: HTTP, TLS. 무엇을 주고받을지
전송 (4) :: TCP, UDP. 포트로 프로그램을 찾는다
네트워크 (3) :: IP. 어느 길로 갈지. 라우터의 자리
링크·물리 (2·1) :: MAC, 이더넷. 실제 선과 전파
= 실제로 쓰는 TCP/IP 모델은 일곱 층을 이렇게 넷으로 묶은 것이다
```

층마다 주소가 다른 것이 요점이다. 2계층은 MAC 주소로 바로 옆 장비까지만 보내고, 3계층은 IP 주소로 다른 망을 건너가고, 4계층은 포트 번호로 그 컴퓨터 안의 어느 프로그램인지 찾는다.

## 📊 비교

| 계층 | 주소 | 단위 | 대표 장비 | 프로토콜 |
|---|---|---|---|---|
| 4 전송 | 포트 | 세그먼트 | | TCP, UDP |
| 3 네트워크 | IP 주소 | 패킷 | 라우터 | IP |
| 2 데이터링크 | MAC 주소 | 프레임 | 스위치 | 이더넷 |
| 1 물리 | 없음 | 비트 | 허브, 리피터 | 없음 |

## 💡 실제 사례

- **인터넷이 안 될 때** — 케이블이 꽂혔는지, IP를 받았는지, 그 포트가 열렸는지 순서로 아래부터 올라가며 범위를 좁힌다.
- **패킷 분석** — 캡처한 패킷을 열면 프레임, IP, TCP, HTTP가 층층이 쌓여 있어서 어느 층에서 어긋났는지 짚을 수 있다.
- **장비 고르기** — 스위치는 MAC 주소를 보고 같은 망 안에서 넘기고, 라우터는 IP 주소를 보고 다른 망으로 넘긴다.

## 🚫 흔한 오해

- **인터넷이 이 일곱 층대로 만들어져 있다** — 실제 구현은 TCP/IP 4계층이다. OSI는 이야기를 나눌 때 쓰는 공통 언어이지 인터넷의 설계도가 아니다.
- **계층을 거칠 때마다 데이터가 복사된다** — 복사가 아니라 앞에 헤더가 덧붙는 것이다. 받는 쪽은 그 헤더를 순서대로 떼어낸다.
- **계층마다 다른 장비가 있다** — 계층은 장비 구분이 아니라 하는 일의 구분이다. 라우터 한 대 안에서도 1계층부터 3계층까지가 함께 돈다.

## 📝 정리

**"누가 어디까지 맡는지 층으로 갈라 둔 그 틀"** 이라고 읽으면 된다. 층마다 붙이는 주소와 헤더가 달라서, 아래를 바꿔도 위가 그대로 돌아가고 문제가 났을 때 어디를 볼지도 좁혀진다. 실제 인터넷은 이 일곱을 넷으로 묶은 TCP/IP 모델로 구현돼 있다.

## 🧒 열 살에게

외국에 편지를 보낼 때 편지 쓰는 사람, 봉투에 주소 적는 사람, 비행기에 싣는 사람이 다 따로지? 각자 자기 차례만 알면 되니까, 비행기를 배로 바꿔도 편지 쓰는 사람은 하나도 안 바꿔도 돼. 편지가 안 왔을 때도 아래에서부터 배는 떴나, 주소는 맞나 하고 차례로 짚어 볼 수 있어.

- 받는 쪽 컴퓨터는 도착한 신호를 어떤 순서로 풀어내나 → 작동 원리
