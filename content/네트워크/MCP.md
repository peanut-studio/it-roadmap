# MCP (Model Context Protocol)

## 📝 정의

MCP는 **AI 가 바깥 도구를 부르는 방법을 통일한 규약(프로토콜)**이다.

Anthropic 이 만들었고 JSON-RPC 2.0 위에서 돈다. AI 쪽은 도구를 부르는 방법 하나만 알면 되고, 서비스마다 다른 사정은 각 MCP 서버가 안에서 감당한다.

### 이름
Model :: 답을 만드는 인공지능
Context :: 곁에 놓아 주는 재료
Protocol :: 약속
= 붙여 읽으면 "인공지능 곁에 재료를 놓아 주는 약속". 무엇을 놓아 줄지는 사람이 정한다

### 비유
콘센트 규격. 다리미든 노트북이든 같은 구멍에 꽂으면 되고, 새 기기가 나와도 벽을 다시 뚫지 않는다.

### 예
AI 에게 일정 하나를 대신 잡아 달라고 했을 때, 그 AI 가 달력 서비스를 실제로 부르는 통로가 이것이다.

## 🖼️ 그림으로 보기

```도해
흐름: 슬랙에서 찾아달라고 하면 무엇이 오가나
사용자 :: AI 에게 슬랙에서 뭘 찾아달라고 한다
AI :: 붙어 있는 서버에 어떤 도구가 있냐고 묻는다
MCP 서버 :: 도구 이름과 인자 형식을 돌려준다
AI :: 맞는 도구를 골라 인자를 채워 호출한다
MCP 서버 :: 슬랙 API 를 대신 부르고 결과를 담는다
< AI :: 받은 결과로 답을 만든다
= AI 는 슬랙 API 를 모른다. 그건 MCP 서버가 알고 있다
```

## ⚠️ 해결하는 문제

```도해
대조: 도구 열 개를 AI 에 붙이면 무엇이 달라지나
MCP 없이 || MCP 로
붙이는 코드 :: 도구마다 새로 || 규약 하나로
도구 목록 :: 손으로 적는다 || 서버가 알려준다
도구 추가 :: 코드를 고친다 || 서버만 켠다
= 연결 코드를 도구 개수만큼 쓰는 대신 한 번만 쓴다
```

AI 에 슬랙을 붙이고 지메일을 붙이고 깃허브를 붙이면 붙이는 코드를 세 번 쓴다. 인증 방식이 다르고 응답 형식이 다르고 오류 처리도 제각각이다. 서비스 쪽 API 가 바뀌면 붙여둔 코드를 전부 찾아 고쳐야 한다.

MCP 는 그 사이에 규약 하나를 끼워 넣는다. 도구 목록도 사람이 적는 게 아니라 서버에 물어보면 이름과 인자 형식이 돌아온다. 새 도구를 붙일 때 AI 쪽 코드는 그대로 둔다.

## 🧱 구성

```도해
층: MCP 메시지는 어떤 층을 거쳐 가나
도구 호출 :: 어떤 도구를 어떤 인자로 부를지
JSON-RPC :: 그 말을 정해진 메시지 형식에 담는다
전송 :: stdio 로 옆 프로세스에, HTTP 로 원격에
= 위층은 그대로 두고 전송만 바꿔 원격 서버에 붙일 수 있다
```

## ⚙️ 작동 원리

MCP 서버가 내놓는 것은 세 가지다. 읽을 거리인 리소스, 미리 짜둔 지시문 틀인 프롬프트, 실행할 함수인 도구. 읽는 것과 시키는 것을 갈라놓아서 서버마다 어디까지 허용할지 따로 정할 수 있다.

같은 컴퓨터에서 도는 서버는 stdio 로 주고받는다. 표준 입출력을 그대로 쓰기 때문에 별도 포트가 필요 없다. 다른 컴퓨터에 있는 서버는 HTTP 와 SSE 로 붙는다.

## 💡 실제 사례

- **파일 시스템** — 폴더 하나를 MCP 서버로 열어두면 AI 가 그 안의 파일을 읽고 고친다.
- **슬랙** — 지난주 배포 얘기를 찾아달라는 말이 슬랙 검색 도구 호출로 바뀌어 나간다.
- **깃허브** — 열린 이슈 목록을 가져오거나 새 이슈를 만드는 일을 도구로 내놓는다.

## 🚫 흔한 오해

- **MCP 가 AI 모델이다** — 모델이 아니라 모델과 도구 사이의 규약이다. 어떤 모델을 쓰는지는 MCP 와 상관없다.
- **MCP 를 붙이면 AI 가 알아서 다 한다** — 서버가 내놓지 않은 일은 못 한다. 어떤 도구를 내놓을지 적어 넣는 건 사람 몫이다.
- **표준 프로토콜이니까 안전하다** — 형식이 통일된 것과 권한이 통제되는 것은 다르다. 서버가 파일 삭제 도구를 내놓으면 AI 는 그걸 부를 수 있다.

## 🚨 주의사항

- **서버가 내놓는 도구가 곧 권한이다.** 명령어를 그대로 실행하는 도구를 내놓으면 무엇이든 실행될 수 있다. 허용 목록을 두고 걸러야 한다.
- **인자를 믿고 쓰지 않는다.** 경로나 질의문이 인자로 들어오므로 서버 안에서 한 번 더 검사한다.

## 📝 정리

**"이것저것 꽂아 쓰게 만든 그 구멍 규격"** 이라고 읽으면 된다. 서버가 도구 이름과 인자 형식을 알려주므로 AI 쪽은 서비스마다 다른 사정을 몰라도 된다. 형식을 통일한 것일 뿐이라 무엇을 내놓고 무엇을 막을지는 서버를 만드는 사람이 정한다.

## 🧒 열 살에게

벽에 있는 구멍은 집집마다 다 똑같이 생겼지? 그래서 선풍기든 다리미든 새로 사 와도 벽을 다시 뚫지 않고 그냥 꽂으면 돼. 대신 꽂았다고 뭐든 되는 건 아니야 — 꽂은 그 물건이 할 줄 아는 일만 해.
