# WebAssembly (웹어셈블리)

## 📝 정의

WebAssembly는 **여러 언어를 컴파일해 담는 안전한 저수준 코드 형식**이다.

W3C 커뮤니티 그룹이 만든 열린 표준이다. 규격은 첫 목표가 웹에서 고성능 응용을 돌리는 것이라고 적으면서도, **웹에만 기대는 가정을 두지 않아 다른 환경에도 쓸 수 있다**고 못 박는다.

### 이름
Web :: 웹
Assembly :: 기계어에 가까운 말
= 붙여 읽으면 "웹에서 도는 기계어 가까운 말". 다만 웹 전용 가정이 없어 브라우저 밖에서도 돈다

### 비유
악보. 어느 나라 사람이 지었든 같은 기호로 적어 두면 처음 보는 악단도 그대로 연주한다.

### 예
설치 없이 브라우저에서 열리는 사진 편집기나 3D 지도처럼, 무거운 계산을 웹에서 해야 하는 자리에 쓰인다.

## 🖼️ 그림으로 보기

```도해
흐름: C 로 짠 프로그램이 브라우저에서 돌기까지 무엇을 거치나
소스 :: C·러스트·고 같은 언어로 짠 프로그램
컴파일러 :: 기계어 대신 웹어셈블리 모듈로 낸다
호스트 :: 브라우저나 서버 런타임이 그 모듈을 읽어들인다
검증 :: 형이 맞는지 미리 검사한다. 어긋나면 아예 안 돈다
실행 :: 상자 안에서 돈다. 바깥은 넘겨받은 함수로만 만진다
= 언어는 여럿이어도 실행되는 형식은 하나다
```

## ⚠️ 해결하는 문제

```도해
대조: 무거운 계산을 웹으로 옮기면 무엇이 달라지나
웹어셈블리 없이 || 웹어셈블리로
쓸 수 있는 언어 :: 자바스크립트 하나 || 컴파일되는 여러 언어
기존 C 라이브러리 :: 웹용으로 다시 짠다 || 컴파일해 그대로 쓴다
받는 파일 :: 글자로 된 소스 || 작고 빠른 이진 형식
= 이미 잘 돌던 코드를 옮겨 심고, 받자마자 한 번에 훑어 돌린다
```

브라우저가 곧바로 실행하는 언어는 오랫동안 [[JavaScript]] 하나였다. 영상 변환기나 물리 계산기처럼 C 나 러스트로 이미 잘 만들어 둔 것이 있어도, 웹에 올리려면 처음부터 다시 짜야 했다.

웹어셈블리는 그 사이에 공통 형식 하나를 끼워 넣는다. 각 언어의 컴파일러가 이 형식으로 모듈을 내면 브라우저는 그것을 읽어 검증하고 실행한다. 규격이 내건 설계 목표에 이진 형식이 **작을 것**과 **해독·검증·컴파일이 한 번 훑는 것으로 끝날 것**이 함께 들어 있다.

## ⚙️ 작동 원리

규격은 의미를 세 단계로 나눈다. 모듈은 이진 형식으로 배포되고(해독), 형 검사를 포함해 뜻이 통하고 안전한지 확인받고(검증), 그다음에야 실행된다. 실행은 다시 둘로 갈린다 — 임포트를 채워 넣어 인스턴스를 만드는 인스턴스화, 그리고 내보낸 함수를 부르는 호출이다.

모듈 하나에는 함수·테이블·선형 메모리·전역 변수가 담긴다. 선형 메모리는 바이트가 죽 이어진 배열 하나이고 필요하면 늘릴 수 있는데, 지금 크기를 벗어난 자리를 건드리면 트랩이 나서 실행이 그 자리에서 멈춘다.

바깥과의 통로는 임포트뿐이다. 규격은 웹어셈블리가 **실행 환경에 대한 주변 접근 권한을 전혀 주지 않으며**, 입출력이든 자원 접근이든 운영체제 호출이든 임베더가 넘겨준 함수를 부르는 방식으로만 할 수 있다고 적는다. 무엇을 넘겨줄지가 곧 권한이라, 그 선은 호스트가 긋는다.

브라우저 밖도 방식은 같다. Node.js 는 WASI 규격 구현을 두어 POSIX 를 닮은 함수 묶음으로 운영체제에 닿게 하고, Go 는 js/wasm 아키텍처로 컴파일할 때 `syscall/js` 로 호스트 환경에 접근한다.

## 💡 실제 사례

- **기존 C 라이브러리 웹에 올리기** — 영상·이미지 처리 코드를 다시 짜지 않고 이 형식으로 컴파일해 페이지 안에서 부른다.
- **브라우저 밖에서 돌리기** — Node.js 는 WASI 구현을 두어, 웹어셈블리 프로그램이 환경 변수와 열어 준 폴더에 닿게 한다.
- **다른 언어에서 내보내기** — Go 는 js/wasm 아키텍처로 컴파일해, 호스트 환경을 만지는 통로를 표준 패키지로 받는다.

## 🚫 흔한 오해

- **웹어셈블리를 쓰면 자바스크립트가 필요 없다** — 코어 규격은 화면을 만지는 방법을 정하지 않는다. 무엇을 만질 수 있는지는 환경마다 따로 정한 API 와 호스트가 넘겨준 함수가 정한다.
- **브라우저 안에서만 돈다** — 규격이 웹 전용 가정을 두지 않는다고 스스로 적는다. Node.js 처럼 브라우저 밖에서 돌리는 자리도 규격이 말하는 임베딩 환경 하나다.
- **웹어셈블리로 바꾸면 무엇이든 빨라진다** — 규격이 내건 것은 네이티브에 가까운 속도라는 설계 목표다. 바깥과의 통로는 임포트뿐이라, 하는 일이 대부분 바깥을 만지는 것이라면 그 통로는 그대로 남는다.

## 🚨 주의사항

- **상자 안이라고 다 안전한 것은 아니다.** 규격도 하드웨어 수준의 부채널 공격에는 취약할 수 있다고 적고, 격리는 임베더가 알아서 마련하라고 넘긴다.
- **런타임마다 격리의 뜻이 다르다.** Node.js 문서는 자기 위협 모델이 일부 WASI 런타임 같은 안전한 격리를 제공하지 않으며, 권한 기능은 지원하되 그것이 보안 모델을 이루지는 않는다고 밝힌다.

## 📝 정리

**"여러 언어를 한 형식에 담아 어디서나 같게 돌리는 그 이진 코드"** 라고 읽으면 된다. 읽어들인 모듈은 실행 전에 검증을 통과해야 하고, 바깥은 호스트가 넘겨준 함수로만 만질 수 있다. 그래서 "무엇을 할 수 있는가" 는 이 형식이 아니라 그것을 품은 환경이 정한다.

## 🧒 열 살에게

악보를 생각해 봐. 어느 나라 사람이 지은 곡이든 같은 기호로 적어 두면, 처음 보는 악단도 그대로 연주할 수 있지? 이건 컴퓨터가 읽는 악보야 — 어떤 말로 지었든 같은 모양으로 적어 두면 어디서나 똑같이 연주돼.
