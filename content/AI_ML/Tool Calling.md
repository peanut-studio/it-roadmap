# Tool Calling (도구 호출)

## 📝 정의

Tool Calling 은 **모델이 시키고 앱이 실행하는 방식**이다.

모델은 글을 지을 뿐 바깥에서 아무것도 못 한다. 그래서 쓸 수 있는 도구의 이름과 입력 모양을 미리 알려주면, 모델은 필요할 때 "이 도구를 이 값으로 불러 달라"는 요청을 돌려준다. 실행은 앱이 한다.

### 이름
Tool :: 바깥 일을 하는 것
Calling :: 부르기
= 붙여 읽으면 "도구를 부르기". 부르기만 하고 실행은 남이 한다는 것이 이름에는 안 적혀 있다

### 비유
식당 주문서. 손님이 적어 낸 종이가 요리를 하지는 않는다. 주방이 한다.

### 예
AI 에게 오늘 날씨를 물으면 잠깐 멈췄다가 답이 나온다. 그 멈춘 사이에 바깥을 한 번 다녀온 것이다.

### 직접
AI 앱에 오늘 날짜를 물어보라. 맞히면 바깥을 다녀온 것이고, 엉뚱한 날을 대면 배운 것만으로 답한 것이다.

## 🖼️ 그림으로 보기

```도해
흐름: 모델이 도구를 쓴다는 것은 실제로 무슨 일인가
앱 :: 쓸 수 있는 도구의 이름과 입력 모양을 미리 알려준다
모델 :: 필요하면 "이 도구를 이 값으로" 라고 돌려준다
앱 :: 그 도구를 진짜로 실행한다
< 모델 :: 실행 결과를 받아 사람이 읽을 답을 짓는다
= 모델은 부탁을 적어 줄 뿐, 손을 쓰는 것은 언제나 앱이다
```

## ⚠️ 해결하는 문제

```도해
대조: 모델에게 바깥일을 시키려면 어떻게 하나
도구 없이 || 도구 호출로
오늘 환율 :: 모른다 || 불러서 본다
일 시키기 :: 말만 한다 || 실제로 한다
모르는 값 :: 그럴듯이 지어낸다 || 받은 값을 쓴다
= 모델을 바깥과 잇는 통로가 이것 하나다
```

모델은 학습이 끝난 시점에 멈춰 있다. 그 뒤에 생긴 일도, 이 회사 안에만 있는 값도 모른다. 모르는 것을 물으면 모른다고 하는 대신 그럴듯한 값을 지어내는 쪽이 더 흔하다.

도구 호출은 그 벽에 문을 낸다. 다만 문을 여는 손은 앱 쪽에 있다. 모델이 돌려주는 것은 요청일 뿐이고, 그 요청을 그대로 실행할지 막을지는 앱이 정한다. 이 자리가 [[Prompt Injection]] 을 막는 마지막 관문이기도 하다.

## ⚙️ 작동 원리

한 번의 대화가 아니라 두 번의 왕복이다. 앱은 먼저 도구 목록을 붙여 묻고, 모델은 답 대신 "도구를 부르겠다"는 표시와 함께 도구 이름·입력값을 돌려준다. 앱이 그것을 실행한 뒤, 실행 결과를 대화에 덧붙여 다시 한 번 묻는다. 두 번째 요청에서야 사람이 읽을 답이 나온다.

제공자가 대신 실행해 주는 도구도 따로 있다. 검색 같은 것은 앱이 손댈 것 없이 결과만 돌아온다. 그때도 실행하는 쪽은 모델이 아니라 그 제공자의 기계다.

도구를 알려주는 일에도 값이 든다. 도구 이름과 설명과 입력 모양이 전부 매 요청마다 함께 실려 가므로, 안 쓰는 도구를 잔뜩 매달아 두면 부르지도 않은 것에 요금이 붙는다.

## 💡 실제 사례

- **사내 재고 조회** — "이 모델 재고 있나요"에 창고 시스템을 불러 숫자를 보고 답한다.
- **일정 잡기** — 빈 시간을 달력에서 읽어 오고, 확정도 달력에 써 넣는다.
- **코드 고치기** — 파일을 읽는 도구와 쓰는 도구를 쥐여 주면 저장소를 직접 손본다.

## 🚫 흔한 오해

- **모델이 도구를 직접 실행한다** — 아니다. 모델이 돌려주는 것은 "이걸 불러 달라"는 요청이고, 실행하는 것은 앱이다.
- **도구를 많이 달수록 똑똑해진다** — 도구 설명이 전부 매 요청에 실려 간다. 비슷한 도구가 여럿이면 고르다 틀리기도 한다.
- **도구를 달면 시키는 대로만 한다** — 언제 부를지는 모델이 정한다. 반드시 부르게 하려면 따로 못박아야 한다.

## 🚨 주의사항

- **실행 직전이 마지막 관문이다.** 모델이 부르라고 한 것을 앱이 그대로 실행하면, 문서에 숨어 든 지시도 그대로 실행된다.
- **되돌릴 수 없는 일은 사람에게 묻는다.** 읽는 도구와 지우는 도구를 같은 무게로 쥐여 주지 않는다.

## 📝 정리

**"부탁은 모델이, 실행은 앱이 하는 그 주문서"** 라고 읽으면 된다. 모델은 도구 이름과 입력값을 돌려줄 뿐이고, 실제로 손을 쓰는 것은 언제나 앱 쪽이다. 그래서 무엇을 실행할지 막는 자리도 앱에 있다.

## 🧒 열 살에게

식당에서 종이에 "김치찌개 하나" 라고 적어 주면 그 종이가 요리를 하지는 않지? 주방이 그걸 보고 끓여서 내오잖아. 얘도 무얼 해 달라고 적어 내밀 뿐이고, 실제로 움직이는 건 다른 쪽이야.
